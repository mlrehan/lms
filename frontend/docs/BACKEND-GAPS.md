# Backend gaps

What the console does **not** offer, and why.

Every item here is a feature the brief asked for that the LMS API does not
support. None of them is faked: there is no screen that pretends to reset a
password, no form that collects data nothing stores, and no "Coming soon"
page. Where the absence is visible to a user, the screen says so in plain
words at the point they would have looked for it.

This file is the authoritative list. If a reviewer asks "where is X?", the
answer is here or it is a bug.

Verified against the API surface as generated by
`frontend/scripts/generate_api_types.py` — **160 paths, 235 operations, 97
permissions, 6 roles**.

---

## 1. Authentication and account self-service

| Missing | Evidence | What the console does instead |
|---|---|---|
| **Forgot password / reset** | No `/auth/password/reset*` route; no email sender anywhere in `backend/` | The sign-in screen has no "Forgot password?" link. It says an administrator can set a new one. `PUT /users/{id}/password` is that path. |
| **Email verification / account activation** | No verification route or token model | Accounts created through `POST /users` are usable immediately; the Create account dialog says the administrator *is* the vouching step. |
| **Self-registration** | No public `POST /auth/register` | There is no sign-up link. |
| **MFA / TOTP / backup codes** | No MFA tables, routes or schemas | Nothing in the UI references MFA. |
| **Trusted devices** | No device model | `remember_me` on sign-in issues a longer-lived refresh token; that is the whole feature. |
| **Editing your own profile** | `PATCH /users/{id}` requires `user.update`; there is no `PATCH /auth/me` | `/account` shows the profile read-only and states that a caller without `user.update` must ask an administrator. A caller who *does* hold it gets an "Edit my profile" link to their own user page. |

## 2. Identity governance

None of the following exists in the API in any form:

- **Impersonation.** `user.impersonate` is in the permission catalog and is
  granted to `SUPER_ADMIN`, but **no route checks it** — the capability is
  declared and unimplemented. The console offers nothing.
- **Invitations** for institution accounts (organizations have their own
  member-invite flow; individual users do not).
- **Access requests, approval workflows, just-in-time access, access
  reviews/recertification, separation-of-duties rules.**
- **Service accounts and API keys.**
- **SSO / OIDC / SAML / SCIM provisioning.**
- **Per-user permission overrides.** Authority comes from roles only; there is
  no allow/deny override table.
- **Bulk user operations and user export.** `GET /users` pages, but there is
  no CSV export or multi-select action endpoint.
- **Multi-tenancy.** `Organization` is a *corporate sponsor* (an employer
  whose staff are enrolled), not a tenant. There is one institution.

## 3. Things the API models but does not deliver

- **Notification channels.** `NotificationChannel` models `EMAIL`, `SMS` and
  `PUSH`, and only `SYSTEM` is ever written. The preferences endpoint returns
  a `channels_note` saying so, and the console renders that note rather than
  offering per-channel switches that would do nothing.
- **Realtime.** There is no WebSocket or SSE endpoint. The unread badges in
  the top bar poll once a minute, and the code says that is what they do.

## 4. Response shapes that limit a screen

These are not missing features; they are fields the list endpoints do not
return, which changes what a table can show.

| Endpoint | Gap | Effect |
|---|---|---|
| `GET /sessions` | Returns `SessionSummary` — no batch, course or tutor | The Timetable lists time, platform and room only. A banner on the screen says so; opening a session shows all three. |
| `GET /batches` | Returns `BatchSummary` — no course | The Batches table cannot show the parent course. Opening a batch shows it. |
| `GET /batches` | No `query` parameter | Batch pickers list up to 200 and filter client-side; the enrollment-transfer dialog asks for a batch id and says why. |
| `PUT /courses/{id}/tutors` | Accepts `public_id`s, while `CourseResponse.tutors` returns **usernames** | Editing a course's tutors needs `user.read` as well, to map one to the other. Without it the console shows the current tutors read-only and explains why. Same for `PUT /exams/{id}/invigilators`. |
| Resource sharing | No `GET` for "who is this shared with" | The share panel can add a share but cannot list existing ones, and says so. |
| `PATCH /announcements/{id}` | No `course_id` / `batch_id` | An announcement's audience is fixed at creation. The edit dialog states this. |
| `POST /enrollments/{id}/transfer` | `TransferRequest` carries only `target_batch_id` | No option to discard the previous enrollment; the dialog says the history is always kept. |
| `GET /settings` | Free-form key/value; no schema endpoint | The Settings screen is a key/value editor with a warning that it cannot validate a value or tell you which keys the server reads. There is deliberately **no** typed "password policy" or "lockout threshold" form, because no such endpoint exists. |
| Exam results | No candidate roster when an exam is not scoped to a batch | The mark sheet derives candidates from the batch. Unscoped exams show only students who already have a result, and the screen explains that. |
| `PUT /assignments/{id}/submission` | Takes `content` and file *metadata*; there is no upload endpoint for a submission | A `FILE_UPLOAD` assignment tells the student to upload under Resources and paste the link. |

## 5. Deliberate non-features

- **No "create permission" control.** A permission row that no
  `require_permissions(...)` call checks grants nothing. Offering it would
  look like authority and be inert — worse than an obviously missing feature.
  Permissions are added in `backend/core/permissions.py`, beside the check
  that enforces them.
- **No role rename.** `RoleUpdateRequest` carries a description only: the role
  *name* is its identifier and is referenced by grants and by seeded data.

## How to re-derive this list

```bash
python frontend/scripts/generate_api_types.py
python frontend/scripts/generate_permissions.py
```

Both read the running FastAPI application's own OpenAPI document and
permission catalog. If a gap above is closed in the backend, regenerating
turns the missing type into a present one and the corresponding screen can be
built against it.
